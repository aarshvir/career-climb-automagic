# Jobvance MVP repair contract

Scope: startup, auth, CV ingestion, factual tailoring, document export and manually confirmed application tracking for a **free beta**. Payment adapters are prepared for future eligibility/approval and sandbox verification; live billing is disabled. The owner reports no registered entity, licence or permit, and does not plan incorporation for a year. Do not activate live billing or infer permission to trade from a provider's technical support for individual sellers. Preserve existing data and working-tree changes. No fabricated outcomes, universal ATS scores, auto-submission claims, or browser-authorized paid plans.

Existing stack remains React/Vite, Supabase auth/storage/Postgres/edge functions. The active workspace is at `/dashboard`; the product name "workspace" does not create a `/workspace` route. Existing jobs may be retained as legacy data but never invented on errors. Existing upload data is retained; new normalized records can be created on explicit user import.

New data model, owned by backend agent:
- `cv_documents`: id, user_id, storage_path, original_filename, mime_type, byte_size, text_content, created_at.
- `application_packs`: id, user_id, resume_id nullable on original deletion, request_id, job_title, company (may be blank), job_url nullable, job_description, original_text, tailored_text, matched_keywords (text[]), missing_keywords (text[]), status (draft/approved), created_at. Internal fields request_fingerprint and credit_grant_id support server metering/idempotency. Server creates and meters packs; users may update only their own reviewed tailored_text/status.
- `tracked_applications`: id, user_id, pack_id nullable, job_title, company, job_url, status (saved/applied/interview/offer/rejected/withdrawn), notes, applied_at nullable, follow_up_at nullable, created_at, updated_at. Status reflects explicit user report, not automated submission.
- Server-owned billing tables: `billing_entitlements`, `billing_credit_grants`, `billing_orders`, `billing_payments`, `billing_refund_adjustments`, `billing_payment_events`. Frontend gets `get-entitlement` response `{creditsRemaining:number, expiresAt:string|null, billingConfigured:boolean,billingMode:'test'|'live'|null,paymentProvider:'paddle'|'stripe'|null}`. One free pack per account supports beta validation. The future paid pass is a proposal: $29 USD before applicable tax adds ten packs for 30 days from the successful server payment event; no renewing subscription or practitioner review. Browser choices, local storage and payment-success UI never grant credits. Sandbox paid grants cannot be used in live mode.

Private bucket: `cv-documents`. User folder prefix `${userId}/`; private downloads via authenticated requests or expiring links. PDF/DOCX/TXT, maximum 5 MB; reject scanned/empty/unparseable inputs with correction option. Reviewed CV text is 80–60,000 characters; job descriptions 80–20,000. Browser extracts content for user correction before upload/persistence. Metadata failure rolls back storage; never claim success without both. New workflow sends no CV to an external AI or payment provider.

Functions:
- `tailor-cv` POST authenticated body `{resumeId,jobTitle,company,jobUrl,jobDescription,requestId}`; returns `{pack:ApplicationPack}`. Company may be blank; empty jobUrl normalizes to null, otherwise it must be HTTPS without embedded credentials. Grounded tailoring compares English vocabulary and conservatively reorders explicit bullet blocks, preserving factual wording and section boundaries; ambiguous continuations stay in place. Matched/missing vocabulary explains relevance, not an ATS score. Atomic server credit consumption, owned CV checks, UUID+fingerprint idempotency and honest failures. Extraction/ranking works without an external AI API. Advertise precisely this capability.
- `get-entitlement` authenticated POST no input; response above.
- `create-checkout` authenticated POST `{requestId}`. Paddle is the default provider (`JOBVANCE_PAYMENT_PROVIDER=paddle`); it returns `{provider:'paddle',transactionId,billingMode}` for a server-verified one-time USD $29 tax-exclusive catalog price, quantity one, with owned custom_data. The frontend opens the official Paddle.js overlay with a matching public client token; no invented hosted URL. A durable creation claim suppresses duplicate transaction creation; uncertain provider timeouts require recovery rather than assuming undocumented API idempotency. Stripe is an optional explicitly selected adapter, returning `{provider:'stripe',url,sessionId,billingMode}`. Its success/cancel URLs return to `/dashboard?checkout=success` or `/dashboard?checkout=cancelled` (success also includes session_id). No client price, credits or user authority.
- `paddle-webhook`: exact-body Paddle HMAC signature verification, five-second timestamp tolerance and durable event ledger. Only transaction.completed for an already server-bound order, expected one-time price/line/amount/currency/quantity and environment can grant capacity. Approved refund adjustments from adjustment.created/updated fetch and verify the related transaction, deduplicate adjustment IDs and revoke only unused capacity from that purchase. Pending/rejected refunds do not revoke; out-of-order tombstones prevent delayed completion restoring refunded capacity.
- `stripe-webhook`: optional Stripe signature-authenticated adapter, with durable deduplication, amount/product/mode checks and purchase-specific unused-credit revocation. Browser success redirect never grants capacity. Both adapters are unavailable unless billing is explicitly enabled and validly configured.

Live activation requires valid HTTPS configuration/support contact plus `JOBVANCE_LIVE_BILLING_REVIEWED`, `JOBVANCE_COMMERCIAL_TERMS_REVIEWED` and `JOBVANCE_SELLER_ELIGIBILITY_REVIEWED` all explicitly true; Paddle additionally requires `JOBVANCE_PADDLE_MERCHANT_APPROVAL_REVIEWED=true`. These flags represent completed manual reviews and are not evidence or substitutes for actual permission/approval. Under the owner's current no-licence/no-permit status, keep them absent/false and `JOBVANCE_BILLING_ENABLED=false`. A free-beta deployment does not require payment keys or merchant onboarding.
