# Product-version rotation — bounded edge review

The release coordinator observed in the actual provider Test checkout that changing a product's localized rule also changed an existing ready checkout's displayed price. The coordinator restored that old product's earlier price. New prices therefore require new provider product versions; stored checkouts must not be repriced by editing their original provider product. The provider observation and restoration receipts belong to the coordinator's native acceptance record.

Fresh authenticated quote candidates must match both the current catalogue version and the current configured product for their plan and mode. A focused orchestration test rejects an old product candidate before any provider call and accepts an exact new candidate only after validating that new product, its fixed localized rule and preview. Stored quoted history remains independent of the current map: earlier INR 2,799 and EUR 25.99 ready checkouts return the original URL and money without any provider read or repeated POST, while uncertain originals remain held. Existing paid, renewal, refund and cancellation paths continue to use the original order and product.

The review also found and fixed a separate legacy USD recovery defect. Unquoted USD checkout recovery previously selected today's configured product before claiming the original request; rotating products would cause a request conflict. The edge now reads that exact owner's original order, selects its stored product, then makes the same session/generation-bound SQL claim before returning any URL. Ready and uncertain originals perform no provider reads. A genuinely new unquoted USD action uses today's configured product. Only a newly acquired checkout claim may validate a product and begin the provider POST; any known pre-POST failure remains retryable, while ambiguous provider writes retain the existing no-repeat boundary.

Tests include the actual edge entrypoint returning an original USD ready URL after current configuration rotates, with zero provider HTTP calls; fresh unquoted USD using the new product; original claim rejection returning no URL and making no provider call; current quote map enforcement; and rotated quoted-history recovery. Response schemas, paid-access logic, account/run/source behavior and payment validators are unchanged.

The shared current version is now `loop-local-2026-10-18-v3`; amounts and rounding inputs are unchanged from v2. Bounded independent review of `20261018111136_job_loop_versioned_price_products.sql` (SHA-256 `70828f9bfea9ad327d3139032a30343080ab8327e65654398d5808ea5f4e93f9`) verified all six exact coordinator-supplied Live/Test plan IDs. The migration retires v2 admission and copies its 54 exact monetary rows into v3 using six distinct new products. It does not edit original quotes, orders, subscriptions, paid periods, accounting anchors, routines or ACLs. Transactional guards require the complete old catalogue, all 54 new rows, six distinct products and no reuse of a historical product ID. No blocker was found in this data-only migration.

Final targeted validation: 157 cases across six edge/handler/Test-isolation and v2/v3 SQL files, application TypeScript, all four Live/Test billing/webhook Deno checks and `git diff --check` passed. Earlier in the same review, 118 integrated SQL cases across four files passed before the v3-only catalogue switch.
