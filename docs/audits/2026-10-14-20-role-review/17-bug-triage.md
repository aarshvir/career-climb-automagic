The founder cannot reliably join a reported symptom to a failed stage. Add a server-issued event reference and allowlisted operation, release, phase, code, timestamp and recovery class; retain coded state on the run. Offer an explicit “Copy diagnostics” action containing these fields and the route template. Exclude CV/vacancy text, email, full URLs/query strings, tokens, receipt secrets and arbitrary error messages; do not silently upload local CV-check data. **Accept:** a synthetic failure joins client reference, worker event and run summary; privacy canaries never appear in copied/stored diagnostics; account access remains enforced. **Dependencies:** shared API/run schema, support UI. **Effort:** 2–4 days; **cost:** engineering and small bounded storage, no new service required.

## One practical founder workflow

1. Check `/admin` once daily and after releases: new bug receipts, blocked/degraded reasons, scheduler freshness and uncertain spend. Open private text only when needed.
2. Group duplicates by operation + release + reason, attach one redacted reference, expected/actual behavior and minimal fictional reproduction. Assign P0 only to evidenced outage, data loss or security impact; P1 blocks pilot expansion, P2 is iterative friction, P3 is later.
3. Contain the affected route or scheduler first when warranted. Allow automation only to classify/deduplicate and retry explicitly idempotent operations; no automatic patches, deploys, cap increases, approval changes, erasure or uncertain-call replay.
4. Fix locally, add a failing-then-passing regression for the cause, review the exact change, run relevant boundaries and a fictional upload → approve → download smoke test. Publish only the reviewed artifact; preserve the prior version and additive schema compatibility. Reopen on recurrence, otherwise record verification and close.

Build BT-01/02 first, then BT-03/04 together. Do not install Sentry, session replay, a separate incident platform, auto-fix agents or 24/7 paging merely to appear enterprise-ready. Actual recovery drills, provider invoice reconciliation and real user reproduction remain unverified.
