The public experience has a useful, consistent starting point for all three audiences. Students receive project context without being credited with professional experience; MBA users can connect earlier work and projects; working professionals can reuse facts and track a next action. Fictional examples and wording-only findings are clearly labelled. Keep these strengths. In source, Loop already supplies a state-dependent next-action card and a four-stage overview (`JobLoopPanels.tsx:14–39`); do not redesign it as an empty dashboard.

**UX-01 — P2: test a shorter first-input sequence.** Observed: the user must enter a role on a separate screen before adding CV text, then paste the vacancy. Source: `CvCheck.tsx:384–388`. The first useful comparison arrives after three continuation actions, despite the role being available in most vacancies. This is a friction hypothesis, not measured abandonment. Test a common intake layout: **CV → role + vacancy → evidence**. Let the user confirm the role explicitly; preserve the no-finished-CV starter for students and career changers. Success: all three persona tasks reach the same valid comparison with one fewer screen and no increase in wrong-role or unchecked-source errors. Dependency: validation/progress updates. Estimate: 1–2 engineering days, then pilot observation.

**UX-02 — P2: connect evidence to the edit that resolves it.** Observed: four fictional findings already make a tall mobile page, with the continuation below the findings; review then presents a full CV textarea while supporting passages move into an accordion. Source: `CvCheck.tsx:389–390`. Maintaining the requirement, context and edited passage mentally is especially demanding for MBA pivots and experienced candidates with long CVs. Proposed shared wireframe: **“3 findings need your review” → requirement list → selected requirement / source passage / own edit → recheck**, retaining an accessible full-document view. Provide a clear “Continue to full CV review” action without implying every gap must be filled. Success: pilot users can trace an edit to its requirement and preserve academic/team context without repeated page hunting. Dependency: stable finding-to-passage references. Estimate: 2–4 days.

**UX-03 — P2: unify private readability and public design tokens.** Source-confirmed: `JobLoop.css:1` declares blue; `index.css:13` uses green primary. Loop help is 11 px, consent 12 px, and some stage/time information 10 px (`JobLoop.css:31,77,140–146`). These are readability and cohesion concerns, not automatic WCAG failures. Use common semantic tokens; make consequential permissions/help at least a comfortably readable body scale, reserve tiny text for nonessential metadata, and retain mobile 16 px inputs. Success: source-backed fixture screens at 390 px and 200% zoom retain readable consent, labels and actions without clipping. Dependency: shared token ownership and fixture render. Estimate: 1–2 days; no new service cost.

**UX-04 — P2: make private work locations recoverable.** Source-confirmed: Loop initializes `tab` to `today` (`JobLoop.tsx:105`); sidebar changes local state (`:350`), with explicit focus movement only for one Today action (`:356`). Inferred: remounting loses the selected section, and Back cannot represent section changes. Keep private identifiers out of URLs, but support safe section routes/query state and move focus to the new section heading after navigation. Success: refresh, Back and task-help return restore the intended section; keyboard users hear the section change. Dependency: router and existing draft safeguards. Estimate: 1–2 days.

**UX-05 — P2: stage the final approval workload.** Source-confirmed only: step six combines full CV, optional source reuse, PDF settings/preview, findings, two attestations, approval, four downloads, next vacancy and optional account saving (`CvCheck.tsx:391–395`). Busy professionals face many simultaneous choices; new graduates may not know why PDF needs extra work. Use **1 Read final wording → 2 Choose format and preview required layout → 3 Confirm and approve → Download**, then reveal reuse/save. Retain exact-byte preview and source invalidation. Success: a pilot user can explain the remaining prerequisite for every disabled download, and edits still invalidate approval. Dependency: document validity state. Estimate: 2–3 days.

Prioritize evidence-to-edit navigation, final approval sequencing and private typography; test shorter intake and section recovery next. Observe one real task per audience without inventing completion statistics. Do not build three separate persona products, an AI CV score, auto-apply, mandatory video onboarding or a wholesale visual rebrand now.
