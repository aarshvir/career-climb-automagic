## Findings and acceptance

**QA-01 — P2: an optional private save can block the local task indefinitely.** Source-confirmed mechanism; occurrence on live is unverified. `CvCheck.tsx:323–331` sets the same global busy state used by local download/back/reset controls and clears it only after the save settles. `free-check-api.ts:61–120` and the configured Supabase client provide no application deadline or cancellation path. A request that remains pending can strand an otherwise approved local CV; this is different from the tested rejected-save case. Separate account-save progress from local export readiness and add a bounded deadline, preserving the same request reference when the outcome is uncertain. Acceptance: a never-settling save permits approved TXT/DOCX exports and navigation; deadline feedback explains uncertainty; retry uses the original reference; late results after account/edit changes remain suppressed. Dependencies: frontend/API owner and existing idempotency contract. Effort1–2engineering days; no vendor spend. Required before widening the pilot.

**QA-02 — P2: the secondary Pages workflow can publish the wrong artifact.** Source-confirmed in `.github/workflows/deploy-testcodex-pages.yml:26–48`: build failure is swallowed, and the existing `public` directory overwrites `dist` as the selected output. The deploy job depends on that build job, not the separate CI result. This can make a testcodex preview appear deployed while omitting the built application. Its current execution and any production impact were not checked. Make this Vite workflow fail on build errors, upload only validated `dist`, and require its checks; retire the workflow if no longer used. Acceptance: deliberate build failure yields no deployment; successful artifact contains generated index and referenced assets; a testcodex route smoke passes. Dependencies: repository workflow owner. Effort0.5–1day; no new service cost. Pilot-required if this preview is still used.

**QA-03 — P2: browser seams remain outside the repeatable release gate.** Source-confirmed coverage gap: Vitest uses jsdom (`vitest.config.ts:9`), journey tests replace downloads/PDF previews (`cv-check-journey.test.tsx:13–18`), and OAuth tests replace auth/session exchange (`check-auth-handoff.test.tsx:17–20`). The passing suite cannot establish production worker URLs, real download behavior or real redirect/storage handoffs across browsers. Add a short synthetic guest smoke against the built deployment, plus a controlled fixture-account sign-in/save/reopen exercise when authorized. Acceptance: actual PDF/DOCX/TXT bytes are read back; edit revokes approval; consented refresh survives with approval cleared; a denied OAuth return preserves recoverable work; the deployed commit and browser version accompany results. Dependencies: test runner and isolated fictional fixtures. Effort2–4days; local/open-source execution can avoid recurring spend. Required before pilot expansion.

**QA-04 — P2: document layout evidence needs independent fixtures.** Existing export tests generate simple documents and extract them with the same parser (`document-export.test.ts:29–58`; `cv-extraction.test.ts:36–77`). They prove useful text properties, but not two-column reading order, Word pagination or visual Arabic shaping. Add a small rights-cleared fictional corpus with human-reviewed expected text/order and visual PDF/Word checks. Acceptance: student, MBA and experienced-career examples retain dates, headings and bullet ownership; mixed-script names render; unsupported characters retain the documented DOCX/TXT escape. Dependencies: QA/designer and Word-compatible reader. Effort1–2days; existing readers suffice. Pilot learning item.
