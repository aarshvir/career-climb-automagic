## Findings

**TW-01 · P1 — Retire conflicting operator entry instructions before widening the pilot.** `docs/OPERATIONS.md:5–37,53–67` presents Node 18+, `npm install`, `db:migrate`, `db:seed`, `test:e2e` and `type-check` as current operations. `package.json:6–22` does not define those scripts; `README.md:30–35,96–102` instead specifies Node 24 or supported Node 22, the lockfile and additive reviewed migrations. The older guide also advises blanket `localStorage.clear()` at lines 92–94. A maintainer following the plausibly named guide can fail setup or discard unrelated browser state. Separately, `INTEGRATED-JOB-LOOP-OPERATIONS.md:28,34` directs support changes through Table Editor and says model adapters remain unavailable, whereas `ADMIN-PORTALS-GUIDE.md:15–21,44–50` documents audited portal controls and a dated connection check. This is a documentation contradiction, not proof of a failed live service. Mark obsolete guides historical at their entry, point to one canonical operations index, and give current runbooks a verification date and feature-state source. Acceptance: a fresh maintainer follows only the index through install and non-mutating readiness checks; every listed script exists; support status work follows the current portal; no blanket storage purge is the default. Dependencies: operator owner validates current runbooks/configuration without revealing keys. Estimate: **0.5–1.5 engineering days**, no new service cost. Pilot prerequisite: yes.

**TW-02 · P2 — Make help search understand the words candidates use.** `HelpCenter.tsx:199–209` requires every literal search word to occur. Executing that exact exported function returned `resume → job-loop-controls`, `resume upload → []`, and `lost draft → job-loop-review`; meanwhile `PDF` and `another vacancy` find appropriate existing topics. A CV newcomer searching “resume” is directed toward resuming cloud runs, while an upload answer already exists. Add a small editorial alias/error-phrase map: resume/CV, upload/read file, lost/interrupted draft and sign-in/login. Keep visible topic titles explicit and provide suggested relevant tasks for empty results. Acceptance: these observed queries rank the upload/recovery topics first, existing exact-title searches remain useful, and five pilot participants can locate their next step using their own wording. Dependencies: approved task vocabulary; search engineer. Estimate: **0.5–1 day**, no search vendor or paid model needed. Pilot learning required: yes.

**TW-03 · P2 — Add a public account-access recovery task.** The public help topic list (`HelpCenter.tsx:21–197`) covers draft recovery but no password, missing confirmation email or expired sign-in-link task. `Auth.tsx:133–138,170` and `ResetPassword.tsx:63–66` already contain useful local guidance and a real reset path, so this is a discoverability/content gap rather than broken authentication. Repeat users seeking saved career facts should be able to identify their sign-in method, request the correct recovery action and protect an open check without guessing. Add one compact topic linking `/auth/forgot-password`, explaining existing Google versus password routes, same-browser link instructions, missing/expired emails and the guest `/contact` receipt fallback. Acceptance: a signed-out reader can find the correct existing action without opening a new account; directions match actual auth controls and retain the current no-delivery-guarantee wording. Dependencies: auth owner reviews method-specific instructions; no new authentication feature. Estimate: **0.5–1 day**, no incremental vendor cost. Validate with pilot users.

Order the work as TW-01, then TW-02/TW-03 together. Recheck captions and public playback when publishing an actual content change. Do not buy another avatar service, build separate persona help products, create public API documentation for interfaces that are not public, or expand the article count before these retrieval and maintenance gaps are addressed.
