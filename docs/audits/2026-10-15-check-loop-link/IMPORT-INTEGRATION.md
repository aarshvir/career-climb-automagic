## Candidate behavior

An explicitly imported check retains its exact ID, original vacancy wording, owner, confirmed authentication lifetime and Loop generation. Saving the CV independently does not lose the pending vacancy relationship. Undo restores the preceding draft's identity, including when two checks have identical wording. Route recovery preserves the identity and edited fields, including intentionally empty fields, but requires fresh link consent. An intervening account lifetime destroys recovery of the old imported draft rather than silently stripping attribution.

The vacancy form offers **Save linked vacancy** with an explicit private-save/link confirmation. Existing private-CV, contact, model, inbox, fact and output approvals remain separate. A link does not start a run or approve a CV. Server ownership, exact source comparison, uniqueness and idempotency continue to be enforced by the existing contract and atomic routine.

If the title, company or description changes, saving is blocked until the candidate restores the saved wording or explicitly chooses to keep the edits as a separate vacancy. Surrounding whitespace uses the same ECMAScript trim semantics as the server. Restoring wording retains the entered URL/location but clears link consent. A separate vacancy uses the existing manual-save path, which already excludes linked opportunities from URL deduplication.

Reopening an already linked source shows its current vacancy status and an exact, generation-bound progress link. Retrying the link preserves the existing wording, notes and progress. Contradictory existing provenance blocks the action. Delayed save completion cannot clear newer form edits. A synchronous draft revision also rejects a submit after a field change in the same React batch, before the consent state update renders. Old auth-lifetime or mismatched-generation responses cannot populate the link snapshot.
