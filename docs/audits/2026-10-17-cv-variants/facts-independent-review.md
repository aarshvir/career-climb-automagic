## Corrections identified during review

1. **A future record version could bypass semantic validation.** The new fact control branch originally skipped source validation for every unequal version, assuming an old retry. A caller could supply the next version and wait for another write to make it current before SQL admission. That could reach the weaker SQL structural/literal boundary with an invalid employer context or category. The control now rejects a supplied version above the fresh server version immediately. Only an older original version reaches the exact-replay branch, where SQL must find its original receipt or reject it. The same pattern existed in the unpublished variant-save branch and was corrected there too. Independent integration regressions cover both branches with a hook that would advance the record immediately before SQL.
2. **An impossible fresh-save response was accepted.** The response validator accepted a non-reused fact save paired with a newer current variant revision. The atomic fresh save necessarily holds the exact source revision. The validator now rejects that combination. A newer current variant remains valid for an old retry or a withdrawal against older fact provenance. An independent browser regression covers this distinction.

## Reviewed authority and provenance

Independent facts have their own opaque identity and revision, separate from global claims. Each confirmation binds the exact owner lifecycle, variant ID, variant revision and source hash. Saving a fact changes record ordering but leaves the global profile, global facts, input version, variant source revision and historical run/packet rows intact. Service-only routines use fixed search paths, deny direct table access and share the lifecycle/record lock ordering used by variant source writes. Fact history and request receipts cascade through actual record erasure.

Fresh confirmation uses the existing literal claim validator against the exact selected source and requires the canonical result to equal the submitted text. A shortened context cannot silently expand into a role/date attribution under an earlier confirmation. Cropped or rewritten passages, changed categories and unsupported uncertainty changes require correction. SQL adds bounded structural and complete-line checks; those checks alone are not a claim of semantic fidelity.

Withdrawal binds the displayed fact revision and original source association, so it remains possible after the CV source changes. It clears both confirmation and sharing. A stale withdrawal cannot revoke a newer independently reconfirmed revision. Exact retries return the original saved revision/source association alongside the current fact and current variant; they do not reactivate old permissions or overwrite newer changes.

Passive reads preserve older-source facts as history. They do not call an initializer or declare those facts ready for preparation. The future-use resolver checks ordered exact references, unique membership, current fact revision, current source revision/hash, active confirmation, current sharing, and literal semantics again. It returns detached values. Empty selection is permitted by this helper; future admission must enforce its own minimum usable-evidence requirements. Ownership must already be established by the caller, and future admission must revalidate authority under its atomic run boundary.
