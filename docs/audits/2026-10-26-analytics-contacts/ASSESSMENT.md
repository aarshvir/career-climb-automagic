# Contact completion and first-party journeys

PR32 is integrated onto released v58, including PR31's explicit email-confirmation continuation and v57's signup/first-result repairs. Automated Job Loop remains primary; guided setup stays optional. This change adds required self-reported name/mobile at signup and a recoverable missing-details step, together with actor-checked Acquisition, Journeys, visit and person administration reads. A phone number is not SMS verification.

The initial branch was held for reproduced functional failures. Independent corrections bind contact writes to the synchronously captured owner, actual SDK session discriminator and auth epoch. Exact REST receipts are required; failed/ambiguous writes retain typed details and can recover by a bound read. Existing admitted private-route and dialog drafts remain mounted but inert while the gate is active. A newly blocked private route is not mounted merely to hide it. Unknown/stale authority cannot unlock it.

Measurements now retain original actor, visitor, visit, context, event, batch and page-exposure identities. Delayed bootstrap cannot overwrite a newer SDK callback. Account changes and logout rotate attribution; same-session refresh can update only its original in-memory credential. Stable per-tab visits may survive reload within 30 minutes; invalid stored context is rejected. Immediate route boundaries, idle rollover and BFCache restoration retain their correct page scopes. Incremental visible time excludes hidden time and cannot attach to a later exposure of the same URL.

The browser serializes bounded in-memory batches, requires an exact acknowledgement, and retries the original IDs/measurement after ambiguous failure. Fetch and response-body waits have a 15-second bound. Credentials are never persisted. Typed values are not read; candidate-page control labels are generic, and contact destinations expose only scheme markers. Delivery on browser close is best effort; this is not perfect visitor measurement or proof of attention.

The new endpoint admits an entire 1–25-event/64KiB batch or rejects it. Every supplied token is freshly verified; invalid identity never downgrades to anonymous. There is no positive-token cache. Origin, method, streamed bytes, timestamps, paths, device fields and SQL acknowledgements are checked. Bots receive a distinct ignored receipt.

Five private RLS tables and ten fixed-search-path routines preserve immutable original attribution and exact batch receipts. First sign-in can link previously anonymous browser history once; later accounts cannot acquire another account's visits. Deleted-owner UUIDs remain historical provenance rather than reverting to reclaimable anonymous rows. Device/country are first observations, not retry identity: moving networks cannot invalidate an exact measurement retry. Page time groups by exposure UUID; paid and organic sources differ, and a new account is attributed once to its first recorded owned visit. Collection-start metadata makes incomplete historical comparisons explicit. Owner/operator access and masks remain, and every admin read is audited.

Three separately assigned contexts implemented and challenged contact, endpoint and SQL/admin contracts. A further independent actual-browser-module review found and closed stalled requests, corrupt persisted context and Check-page labels. The SQL/admin reviewer caught mixed response identities, deleted-account/organic/coverage wording and a local Unicode encoding defect; these were corrected before native release. Actual SQL/controller tests include exact operator masks and a full controller→RPC audit path.
