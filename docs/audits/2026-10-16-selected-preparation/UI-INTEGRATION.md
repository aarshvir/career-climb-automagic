# Deliberate saved-vacancy preparation UI

16 October 2026. **Unpublished source only. Public v30 and control15/worker11/OAuth5 remain unchanged.** Both pending migrations are unapplied. This frontend must not be published against the existing handlers; combined independent review and coordinated schema/control/worker/site exposure remain required.

## Implemented behavior

The Loop page now offers a deliberate one-or-two-vacancy chooser and a direct choice from each saved vacancy. The chooser preserves click order and exact IDs, including a third listed vacancy, instead of silently preparing the first available records. Saved descriptions and source status can be inspected before consent. Missing or contradictory source identity blocks preparation without selecting a replacement. Closed or already-progressed applications cannot start a new preparation, while an exact previously submitted request can still be checked without overwriting its later progress.

Preparation uses the existing `start_selected_run` contract, with the displayed generation/version, a stable request UUID, explicit preparation consent and the selected processing route. Source-based rules are the default when available; unavailable methods are not silently replaced. Available model choices require a separate named processing permission. Private saving, imported-check consent, claim clearance, preparation and exact-artifact approval remain separate. No inbox or discovery permission is passed to a selected request.

Consent is invalidated by selection, method, source/provenance, profile/claim, draft, owner, auth authority or lifecycle changes. Synchronous revisions block selection and claim edits submitted in the same React batch. Parent and child guards reject delayed results before they can apply an old snapshot or clear newer work. Direct vacancy choices are bound to owner/auth authority/generation and are not inherited by a refreshed record lifetime.

Ambiguous retries retain the original action, request UUID, generation and version in the mounted page, including switches between Loop tabs and later tracking/unrelated-vacancy changes. Tab return requires fresh confirmation. Confirmed receipts show “Preparation recorded”; a new choice requires another deliberate selection and consent. This is page-memory identity, not durable recovery across a full route unmount, browser refresh or closure. That broader retry recovery remains an acceptance/design consideration before release.

Run history labels selected scope separately from wider discovery and preserves missing-source/earlier-lifetime wording. Existing outputs still require their own evidence review and exact approval before download. The wider discovery action remains separately labelled; its legacy request is not used by the new chooser. Overview and direct-vacancy navigation focus the selected chooser rather than the discovery controls.
