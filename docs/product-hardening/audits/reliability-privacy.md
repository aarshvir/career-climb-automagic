## Boundary assessment

- **Source revision and approval:** Database CAS, source/input versions, exact reviewed text and approval hashes prevent stale factual publication/download. Claim withdrawal and source corrections revoke export authority, including reported application history. UI clears factual/disclosure choices after edits.
- **Ownership and privacy:** Control derives owner from authenticated identity. Repository reads and private paths are owner-scoped, service RPCs are revoked from browsers, and API/Blob responses recheck current owner. Anonymous private endpoint requests independently denied. No candidate account or foreign private record was opened.
- **Source qualifiers and redaction:** Cleared literal claims preserve contribution, negation and forecast qualifications; model input uses eligible phrasing/context plus vacancy, not raw CV/name/contact. Excluded terms suppress/redact output material; the raw saved source still requires user redaction as documented. Initial context classifier gap is R1.
- **Extraction and formats:** 5 MiB upload, 80–60,000 readable characters, 100 PDF pages, UTF-8 TXT, and 2 MiB actual inflated DOCX document XML bounds are present. DOCX ignores external relationships/macros, denies DTD/entities and forged-size ZIP bombs. PDF scans/no OCR, corrupt/password-protected and unsupported glyph/page failures have actionable alternatives. DOCX/TXT can remain usable independently of PDF.
- **Downloads and invalidation:** Server verifies stored bytes against the manifest before issuing 120-second owner-path links; no public bucket. Expired requests can get a fresh link, and source changes deny new links. Previously issued signed links/downloaded copies cannot be retroactively recalled. Stalled browser request recovery is R4.
- **Shared budget and model keys:** Model/provider keys remain server-side. Frontend production validation rejects privileged Supabase keys. Candidate/search and admin reservations share the same monthly locked ledger capped at US$50 and owner-configured lower caps; uncertain reservations retain spending and cannot be blindly replayed. Admin review batch cap is US$5. Erasure does not refund committed paid usage. No real funded call was made by this auditor.
- **Sending/payment boundaries:** Sending and application submission are unsupported control actions. Gmail drafts need separately confirmed recipient/attachment and connection permission; Gmail was not connected here. Source disables checkout unless explicitly configured; supplied hosted QA reports disabled real-money checkout and anonymous actual checkout denied.
- **Scheduler ownership and failure states:** Recurring opt-in, timezone-aware future instants, durable occurrence/lease identity, active-user limits and authoritative pause/cancel guards are present. Missed windows prepare once rather than flooding catch-up runs. Current UI is rules-only. Source failures are reported partial/blocked rather than success or an empty market. R2/R3 concern model-related runtime/API edges.
- **SEO/private routes and rollback:** The generated Worker passed noindex headers for private/auth/admin routes and all 38 public rendered routes; robots excludes private roots and sitemap includes public pages. The actual domain still serves older generic initial HTML and lacks a /loop X-Robots-Tag at the observed time; this is a release gap, not failure of the new generated Worker. **Accept when:** Recognized internship, volunteering and personal-project headings reset context and display accurate badges; ambiguous new section headings must not inherit an affirmative employment/academic label. Assisted work remains partial for a leadership requirement. Preserve full source text and professional-experience safeguards.

**Source:** `src/lib/cv-evidence.ts:sectionFor`, `src/lib/cv-evidence.ts:cvPassages`, `src/pages/CvCheck.tsx:evidence badges`.

### R2 · P2 · Keep the database run lease longer than the bounded model operation

**Reproduce:** With the initial 100-second SQL lease, simulate a valid OpenRouter response at 101 seconds. The real runtime settles one usage row and uploads five artifacts, then phase commit is denied. In a fresh in-memory PostgreSQL instance, the old lease also rejects a simulated 101-second commit.

**Why it matters:** A successful billed model result can fail to publish until recovery or another explicit resume. A competing recovery worker may observe an in-flight reservation and block conservatively.

**Accept when:** Allow a valid response inside the declared 120-second provider deadline to settle/render/commit while the lease remains authoritative. Cancellation, stale-input, owner, token and service-only RPC guards must still deny late/foreign publication. Prove it without real paid calls.

**State:** Local fix independently passed: additive migration extends the run lease to 180 seconds; eight database assertions passed. Hosted migration application was not independently verified.

**Source:** `supabase/functions/_shared/jobvance-openrouter.ts:callRouter`, `supabase/migrations/20261011010000_job_loop_cloud.sql:job_loop_claim_run`.

### R3 · P2 · Reject unsupported paid recurring schedules or persist their explicit processing route

**Reproduce:** The backend accepts a paid daily openai/gpt-6.1-sol schedule with model consent. When OpenRouter is configured, scheduled dispatch stores only model/inbox consent. First preparation compares missing route as direct against openrouter and blocks before reservation or provider use.

**Why it matters:** An accepted supported API schedule repeatedly queues work that cannot prepare. The current customer UI schedules rules only and is unaffected; this is a latent API/legacy-schedule failure, not an observed paid customer run.

**Accept when:** For the rules-only product, reject paid schedules explicitly before persistence/dispatch. If paid recurrence is supported later, persist and display the exact consented processing route, invalidate consent on route changes, and test routed scheduling with no provider substitution.

**State:** Open at initial audit. New paid schedules now reject before persistence; the independent recheck passed. Existing saved paid schedules still need explicit legacy handling.

**Source:** `supabase/functions/_shared/job-loop-schedule.ts:validateScheduleInput`, `supabase/functions/_shared/job-loop-runtime.ts:processDueSchedules`.

### R4 · P2 · Bound private document requests and release stalled download controls

**Reproduce:** Mock the signed private artifact fetch with a promise that never settles. The call receives no cancellation signal and remains pending after ten virtual minutes. The UI download busy state is cleared only when this promise settles.

**Why it matters:** A stalled connection can leave review/download and refresh actions disabled with no fresh-link recovery. The existing descriptive retry errors only run after a rejection or response.

**Accept when:** Use a bounded request/read deadline, cancel stalled work on owner/unmount changes, clear busy state and offer a fresh signed-link retry. Keep the current approval and owner fence. Enforce the byte limit while streaming rather than only after whole-blob allocation.

**State:** Open at initial audit. A narrow 45-second deadline fix independently passed stalled-header/body, fresh-link retry and owner-arrival checks. Whole-blob allocation and immediate owner/unmount cancellation remain separate limits.

**Source:** `src/lib/job-loop-api.ts:fetchLoopArtifact`, `src/pages/JobLoop.tsx:download`.
